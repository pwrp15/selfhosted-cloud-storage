# 自建网盘服务器：配置怎么选、存储放哪里、一年花多少钱，用雨云把私有云盘跑起来

自建网盘这件事，软件那部分基本是免费的。Cloudreve、AList、可道云都能直接下载，Nextcloud 是开源项目，Seafile 社区版也不要钱。真正花钱、也真正决定体验好坏的，是服务器本身——内存够不够、硬盘多大、上行带宽多少、流量怎么算。

所以这篇文章不讲"为什么要自建"这种废话，只解决三件事：你的需求对应什么配置，存储应该放在本机磁盘还是对象存储，以及整套东西一年大概要花多少钱。雨云的机器和存储会作为具体方案贯穿其中，因为它的机房覆盖、免备案选项和对象存储的内网流量规则，恰好对得上自建网盘这个场景。

## 先分清你要的是"私有云盘"还是"网盘入口"

这两件事经常被混在一起，选了不同的软件，后面的配置要求差得很远。

- **Nextcloud**：功能最全，文件同步、在线文档、日历、联系人、多端客户端都有。代价是吃资源，1核2G 跑起来会明显吃力，普遍建议 2核4G 起步，再配上 Redis 做缓存才算流畅。
- **Seafile**：块存储 + 增量同步，大文件和多设备同步的效率比 Nextcloud 好，文件历史版本可以按次数或时间保留，误删好找。需要 MySQL，部署稍微麻烦一点，官方提供 Docker 镜像和安装脚本。
- **Cloudreve**：Go 写的单文件程序，部署最省事。社区版本机存储 + 数据库就能跑，管理后台能设用户配额、分享链接、下载限速，也能把存储策略指向 S3 兼容的对象存储。做个人网盘或者资源分享站很合适。
- **可道云 Kodbox**：界面就是 Windows 资源管理器那套逻辑，国内用户几乎不用学。在线编辑、压缩包解压这些都有，官方一键脚本会自动配好 Nginx + PHP + MySQL。
- **AList**：严格说它不算存储型网盘，而是把已有网盘和对象存储挂到同一个入口，通过网页或 WebDAV 访问。自己不存文件，所以对硬盘几乎没要求。

| 网盘程序 | 部署难度 | 资源占用 | 配置起点 | 适合谁 |
| --- | --- | --- | --- | --- |
| Nextcloud | 中 | 高 | 2核4G + Redis | 需要日历/联系人/多端同步的团队 |
| Seafile | 中 | 中 | 2核2G + MySQL | 大文件、频繁同步、版本管理 |
| Cloudreve | 低 | 低 | 1核1G（Docker 建议 1核2G） | 个人使用、分享站、主要走网页端 |
| 可道云 Kodbox | 低 | 中 | 2核2G | 习惯图形界面、不想碰命令行 |
| AList | 低 | 低 | 1核1G | 已有网盘或对象存储，只要统一入口 |

雨云官方论坛里那篇从零部署 Cloudreve 的帖子里写得挺明确：Cloudreve 需要 1核1G，如果走 Docker Compose 部署则至少要 1核2G；如果打算让服务器本身当存储，就直接买大硬盘、大带宽的机型。

选型上还有一点：如果你的使用场景就是"网页上看文件、发分享链接"，Cloudreve 和 AList 的性价比明显更高；一旦你真的需要手机相册自动备份、多端双向同步、共享日历这些，那 Nextcloud 才是对的那一个，配置预算也得跟着提上去。

## 配置怎么定：内存和硬盘比 CPU 重要

自建网盘不是计算密集型应用。文件上传下载主要压磁盘 I/O 和网络，CPU 只在生成缩略图、打包压缩、转码时才会明显吃紧。所以预算的分配顺序应该是：硬盘 > 内存 > 带宽 > CPU。

- **硬盘**：雨云云服务器在购买页可以把云盘容量在 30GB 到 2000GB 之间调，评测文章中出现的扩容价格是固态 0.4 元/GB/月、机械 0.1 元/GB/月。存照片文档，30–100GB 够用；存影视资源，几百 GB 起步，或者干脆走对象存储。
- **内存**：Cloudreve、AList 1核1G 能跑；可道云 2G 会更稳；Nextcloud 别低于 4G。
- **带宽**：见下一节，这是真正影响体验的一项。

雨云云服务器用 KVM 虚拟化，支持预装宝塔、1Panel 等面板，可选 Linux、Windows，部分地区还有 Mac 系统，操作系统和面板这块基本不用自己从零搭。

## 带宽和流量：自建网盘真正卡脖子的地方

很多人配服务器时盯着 CPU 核心数，结果搭完发现同事下载一个 2GB 的文件还在转圈。原因是云盘的体验瓶颈在上行带宽——也就是从服务器发文件出去的速度。

判断方法很直接：你打算同时给几个人用，就要多少上行。

- 一个人备份照片文档，偶尔下载：10–20Mbps 上行够。
- 家里几个人同时看 1080P 视频：至少 40Mbps 上行。
- 经常传大文件、几个人同时拉素材：100Mbps 级别的线路，或者直接把文件放对象存储走 CDN。

雨云云服务器在计费方式上分了两种口径，买之前要看清：

**流量不限型**：带宽是固定的，跑满也不额外扣流量费。适合长期挂着的网盘、图床、下载站。

**流量叠加型 / 大带宽限流量型**：带宽高、每月给一定流量。雨云的规则是用不完的流量可以逐月叠加，超出后限速到 5Mbps，也可以单独买流量包恢复高速。日本二区评测里给出的流量包价格是 500G 50 元、1TB 80 元。

两种模式价格一样的情况下，选哪个取决于你的使用模式：网盘是"平时安静、偶尔爆发"，大带宽限流量型更合适；如果是持续有人访问的站点，不限流量型更省心。

还有一个绕不开的合规问题：**域名解析到国内机房（江苏宿迁、湖北十堰、广东深圳、重庆等）需要完成 ICP 备案，否则 80/443 端口会被拦**。美国洛杉矶、日本东京、中国香港这几个区域免备案，用域名直接访问省事，代价是延迟高一些。如果你的数据主要自己用，香港通常是延迟和便利性之间比较平衡的选择。

## 存储放哪：本机云盘还是对象存储

这是自建网盘里最容易被忽略、但最影响长期成本的一个决策。

把文件全塞在服务器的系统盘上，好处是简单，坏处是两件事：一是扩容要停机改配置，二是磁盘满了整个网盘就瘫了。另一种做法是把 Cloudreve 之类的程序装在服务器上，文件实际存在 S3 兼容的对象存储里——雨云的对象存储就走这条路。

雨云对象存储的计费项目只有两项：存储空间和流量，不按请求次数、请求类型、内外网分别计费。更重要的是它的流量规则：

- 只计算上行流量（也就是从存储桶往外下载），上传不计流量。
- 同一区域的云服务器和对象存储之间走内网地址互传，上下行都不计流量。

第二条对自建网盘来说价值很大。程序装在湖北十堰的云服务器上、文件存在十堰的对象存储里，那么服务器往存储桶里写文件完全不消耗流量配额。

## 用雨云跑起一个网盘，实际要走几步

以 Cloudreve 为例，整个流程没什么玄学：

1. **买机器**。个人使用选 1核2G 起步（Docker 部署建议这个档），区域优先香港或美国免备案；打算长期放文件就顺带把云盘容量调大。
2. **装系统**。购买时可以选择预装面板或干净的系统，跑 Cloudreve 建议不要预装任何多余软件，少一层环境少一类问题。
3. **部署程序**。最省事的是 Docker：拉 `cloudreve/cloudreve` 镜像，映射 5212 端口，把 `uploads` 和 `conf` 目录挂出来。启动后用 `docker logs` 看日志里打印的初始管理员账号和密码，首次登录立刻改掉。
4. **配置存储策略**。想用本机硬盘就选本地存储；想省服务器空间，就新建一个 S3 策略，把雨云对象存储的 AccessKey、SecretKey、Bucket 名和区域节点填进去，然后设为默认策略。这一步全程在网页后台完成，不用改代码。
5. **放行端口和反向代理**。防火墙记得放行对应端口，否则浏览器会一直转圈。要用域名访问并上 HTTPS，再配一层 Nginx 或 Caddy 反向代理。
6. **（可选）对接离线下载**。需要 Aria2 之类的组件时，在 Docker Compose 里一起加进去，注意 RPC 密钥别用默认值。

如果你想要的是"把百度网盘、阿里云盘、OneDrive 全部聚到一个入口"这种用法，AList 更合适，Docker 一条命令就能跑起来，之后在后台添加对应的存储驱动就行。要在线文档、日历、联系人这些完整协作能力，那就回到 Nextcloud 的路线，配置往上加一档。

无论选哪个，购买前都建议先确认当前的机器规格和存储套餐。

- **小团队协作**：2核4G 跑 Nextcloud（约 50–70 元/月）+ 200GB 平衡套餐（40 元/月），一年千元出头，几个人平分下来比按人头买企业网盘便宜不少。
- **资源分发站**：真正贵的是流量，这种情况应该果断上对象存储 + CDN，而不是硬扛云服务器的带宽费用。

判断标准其实很简单：如果你只是想要一个能存照片、偶尔同步文档的地方，网盘会员更省心；如果你对上传下载速度、文件大小、数据归属有明确要求，自建才是正解，而且用得越久，成本越摊越薄。

## 几个容易踩的坑

**备案**。国内机房必须备案，海外和香港免备案。买之前先定这件事，别等装好了才发现域名打不开。

**上传大小限制**。Nextcloud、ownCloud 这类 PHP 环境默认上传限制往往只有 2M，不改 `upload_max_filesize` 和 `post_max_size`，上传大文件会直接失败。Cloudreve 和 AList 没有这个问题。

**把数据只放在一个地方**。云盘不是备份。系统盘挂了、对象存储误删了，都找不回来。重要文件至少留一份异地副本。

**流量用超**。不开弹性计费时超量会直接停掉上传或下载功能，虽然不会丢数据，但体验会很突兀。心里有个用量预期，或者提前打开弹性计费并设好预算。

## 常见问题

**1核1G 能跑自建网盘吗？**
能。Cloudreve、AList 在这档配置上跑得动，1核2G 用 Docker 部署会更从容。Nextcloud 不行，2核4G 是底线，还得配 Redis。

**自建网盘需要公网 IP 吗？**
需要。云服务器默认就有公网 IP，这正是它比家用 NAS 省事的地方——不用折腾内网穿透和端口映射。

**硬盘不够了怎么办？**
两条路：在雨云云盘上扩容，或者把存储策略切到对象存储，之后新文件直接进存储桶。对象存储的方式可以随时换套餐，升级补差价，也能降级。

**对象存储的流量费会不会失控？**
它的计费项只有存储和流量两项，只算下行。再加上可以随时关掉弹性计费、超量自动停服，正常情况下不会出现意外账单。真正要留意的只有一件事：把公共读的链接挂到高流量页面上。

**自建网盘和 NAS 怎么选？**
NAS 一次性买硬件，长期电费和数据安全自己扛；云服务器按月付费，省掉了公网访问和硬件维护的麻烦，代价是长期租金。短期图省事、需要异地访问，选云服务器；有大量冷数据要长期保存，本地 NAS 更划算。

一句话总结：自建网盘服务器的门槛不在技术，在选型。搞清楚你要的是轻量分享还是完整协作，算出你的上行带宽和存储需求，剩下的部署步骤，一台 1核2G 起步的云服务器加一条 Docker 命令就能搞定。
